## ASD（老師的資料）這條線 —— 有標籤，可以報 Dice

四包 FreeSurfer 資料合併成 520 顆，切成 train 418 / val 51 / test 51。
**val 挑 epoch、test 只跑一次。**

| 資料夾 | 這顆在做什麼 | 最佳 epoch | test Dice | 折疊率 |
|---|---|---|---|---|
| `asd_exp1/` | 最早的一顆，只有 ASD 那包 167 顆（train 149 / test 17）| 0190 | 0.7811 | 0.000% |
| `mix_exp1/` | 第一次混合三包 286 顆（train 258 / test 28），還沒有驗證集 | 0230 | 0.7874 | 0.000% |
| `mix_exp2/` | **換成 520 顆、三段切分的第一顆**。速度場版（程式預設）| 0240 | 0.7972 | 0.000% |
| `mix_exp3/` | 同上，換成**論文 Table I 的位移場版**（`--int-steps 0 --int-downsize 1`）| 0240 | **0.8062** | 0.199% |
| `mix_exp4/` | 位移場 + `--lambda 2.0`，把「換版本」和「平滑懲罰砍半」分開 | 0230 | 0.8005 | 0.053% |

**mix_exp3 vs exp2 高的那 0.009 是怎麼來的**（逐人配對 51 位）：
換版本只佔 **+0.0033**，平滑懲罰砍半佔 **+0.0057**。
折疊率也一樣：0% →（換版本）0.053% →（再砍半懲罰）0.199%。
👉 **擠爆主要是參數造成的，不是版本。**

⚠️ `asd_exp1` 和 `mix_exp1` 的最佳 epoch 是**在 test 上挑的**（當時還沒切驗證集），
偏樂觀約 0.004，不能跟 exp2 之後的直接比。而且 `mix_exp1` 的 test 是另一批人。

## tigerbx 標籤對照組 —— 同一批人、同一個切分，只換去顱骨與標籤工具

| 資料夾 | 這顆在做什麼 | 最佳 epoch | test Dice | 折疊率 |
|---|---|---|---|---|
| `tiger_exp1/` | 對應 `mix_exp1`（286 顆那版）| 0240 | 0.8594 | 0.000% |
| `tiger_exp2/` | 對應 `mix_exp2`（520 顆、速度場版）| 0250 | 0.8621 | 0.000% |
| `tiger_exp3/` | 對應 `mix_exp3`（位移場版）| 0210 | **0.8714** | 0.226% |

🔴 **tigerbx 的 Dice 看起來高 0.065，但它的起點也高 0.057**（0.7453 vs 0.6882）。
扣掉起點之後模型貢獻只差 +0.008。
👉 要講的是「**tigerbx 的標籤本身比較好對**」，不是「配準比較準」。

`mix_exp2/cross_mix_tiger_exp2_exp3/`
交叉評估：把兩邊的模型互換去跑對方的資料。**換去顱骨工具只掉 0.002～0.008**，
比標籤來源造成的 0.065 小一個數量級。

## IXI 主線 —— 沒有標籤，只能看 NCC / SSIM

⚠️ IXI 的 npz 只有 `vol` 沒有 `seg`，**報不出 Dice**。
⚠️ NCC 是含背景的全域相關，已經飽和在 0.986–0.992，分不出模型好壞。

| 資料夾 | 這顆在做什麼 | 最佳 epoch |
|---|---|---|
| `exp1/` | 最早的一顆，用 OASIS 資料（**201 個 .pt，不要遍歷讀**）| — |
| `exp2_IXI/` | 第一次換到 IXI，v1 資料（101 個 .pt）| — |
| `exp3_IXI/` | 沒有 script log，參數不明 | 0295 |
| `exp4/` | `--lambda 0.005`（**501 個 .pt，不要遍歷讀**）| 0069 |
| `exp5/` | `--lambda 0.05` | 0065 |
| `exp6/` | **完全跑程式預設**（等於 MSE + λ0.01），唯一一顆正則化強度正常的 | 0153 |

## 每個實驗資料夾裡通常有什麼

```
mix_exp2/
├── 0240.pt                    最佳 epoch 的權重（只留這一顆，其他已刪）
├── dice_baseline.csv          起點：只做線性對位的 Dice（逐人）
├── dice_baseline_val.csv      同上，驗證集版
├── dice_0240.csv              配準後的 Dice（逐人、逐結構）
├── dice_curve_val.csv         每 10 個 epoch 在驗證集上的 Dice 與折疊率 ← 挑 epoch 用這個
├── dice_curve_analysis.png    上面那份畫成圖
├── loss_curve.png             訓練 loss（總 / 影像 / 平滑）
└── vis_<受試者>/              視覺化，每位 8 張
```

📌 **挑 epoch 只讀 `dice_curve_val.csv`，不要去遍歷 `.pt`。**
📌 `exp1` 和 `exp4` 各有 200～500 個 `.pt`，遍歷會很慢。

## 常踩的坑

- **atlas 版本要跟資料版本一致**，混用會直接報 shape 不合，或安靜地訓練出對不準的模型
- **tigerbx 組評估一定要換 `--atlas-seg`**，忘了的話 Dice 會安靜地低掉約 0.14
- **`--image-loss` 預設是 `mse` 不是 ncc**，想跑 NCC 一定要明寫
- **這台筆電（8 GB）訓練不動這個設定**（25 秒/步），要在機器「AI」上跑
