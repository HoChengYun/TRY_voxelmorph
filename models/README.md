- 以前說的「換成論文的版本 +0.0033」＝ 前兩列加起來：**功勞全在解析度，換成位移場本身是負的**（手冊 §20.5）
- 折疊率：速度場不管半解析度還是全尺寸都是 0% →（換成位移場）0.053% →（再砍半懲罰）0.199%。
  👉 **擠爆主要是參數造成的，版本也有一點，解析度沒有**
- 加寬後折疊率沒變高（0.199% → 0.187%），而且**越難對的人幫越多**（手冊 §23.6）
- **速度場調平滑權重（10-04）**：2 → 1 有幫助（+0.0025），1 → 0.5 就沒再變好；擠爆始終接近 0（權重 0.5 平均 0.0001%）。
  速度場最好的權重 1 是 0.8051，比位移場權重 1（0.8062）少 0.0011，但擠爆少約 2000 倍。
  權重 0.5 時皮質、白質繼續變好，脈絡叢、腦脊髓液這些小結構變差，30 個結構平均起來打平（手冊 §20.5）
- **加寬改速度場（10-05）**：0.8111，跟加寬位移場 0.8114 打平，擠爆從每人約 15,000 點變成 51 位只有 2 位有、最多 2 點。
  預設寬度時速度場還輸 0.0011，加寬後差距看不出來。**目前分數最高又不擠爆的就是這顆**（手冊 §23.9）

⚠️ `asd_exp1` 和 `mix_exp1` 的最佳 epoch 是**在 test 上挑的**（當時還沒切驗證集），
偏樂觀約 0.004，不能跟 exp2 之後的直接比。而且 `mix_exp1` 的 test 是另一批人。

**怎麼看這張表**
- **`--int-steps`**：0 ＝ 位移場版（論文 Table I，不積分）；7 ＝ 速度場版（積分 128 步，程式預設）
- **`--int-downsize`**：速度場版時 ＝ 在幾分之一的解析度上積分（2 ＝ 一半）；位移場版時網路完全不受影響
- **實際平滑權重 ＝ λ × int-downsize**：程式會把平滑懲罰偷偷乘上 int-downsize（手冊 §23.4）。
  所以 mix_exp2 下的是 λ 1.0，實際卻是 2；mix_exp4、mix_exp5 下 λ 2.0 才能跟它對齊
- **U-Net 預設**：encoder `16 32 32 32`、decoder `32 32 32 32 32 16 16`（30 萬參數）。
  **2 倍寬**：`--enc 32 64 64 64 --dec 64 64 64 64 64 32 32`（120 萬參數）

**所有 ASD 實驗都一樣的設定**：`--image-loss ncc`（窗格 9×9×9）、250 epoch × 100 步、學習率 1e-4、batch 1、
atlas `IXI/atlas_mni152_09c_v3.npz`（192×224×192）。Dice 用 `voxelmorph-code/data/labels.npz` 的 30 個結構；
tigerbx 組評估時 `--atlas-seg` 要換成 `IXI\atlas_mni152_09c_v3_seg_tigerbx.npz`。

## 常踩的坑

- **atlas 版本要跟資料版本一致**，混用會直接報 shape 不合，或安靜地訓練出對不準的模型
- **tigerbx 組評估一定要換 `--atlas-seg`**，忘了的話 Dice 會安靜地低掉約 0.14
- **`--image-loss` 預設是 `mse` 不是 ncc**，想跑 NCC 一定要明寫
- **這台筆電（8 GB）訓練不動這個設定**（25 秒/步），要在機器「AI」上跑
- **位移場版的 `--int-downsize` 只是藏起來的 λ 倍數**，不會改網路、也省不到顯存，一律維持 1（手冊 §23.4）
